Overview

This project runs a complete WordPress stack inside a virtual machine, where every image is written by hand from an Alpine base — no pre-built images pulled from Docker Hub.

Three mandatory services, each in its own container:

  • nginx — the only entry point, TLS only, listening on port 443.
  • wordpress — WordPress running on php-fpm, with no web server of its own.
  • mariadb — the database, never exposed outside the Docker network.

They talk to each other over a private Docker network, and the site itself is served at https://jbarthel.42.fr. A few bonus containers sit alongside them: a Redis object cache, Adminer for database administration, and the static server rendering this page.

User guide

The public site lives at https://jbarthel.42.fr. The certificate is self-signed, so the browser shows a warning on the first visit — accepting it is expected here.

The administration panel is at /wp-admin. Two accounts exist: an administrator and a regular author, so the difference in permissions can be shown live.

Credentials are never stored in the repository. They live in the secrets/ directory on the machine running the stack, which is excluded from git. Anyone rebuilding the project has to recreate those files themselves.

Developer guide

Requirements: Docker, Docker Compose and make.

Running make builds every image and starts the stack. make down stops it, and make fclean removes images and volumes for a clean rebuild.

Before the first build, the secrets/ files must exist and the domain has to resolve locally — add jbarthel.42.fr to /etc/hosts, pointing at 127.0.0.1.

Data survives restarts because both the database and the WordPress files are bind-mounted into ~/data on the host. Deleting that directory is what actually resets the installation — stopping the containers does not.
